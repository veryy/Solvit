# 上下文与自动记忆阶段

本阶段参考固定版本的 Operit `api/chat/enhance/ConversationService.kt`：按当前记忆空间读取用户资料，再作为有来源的用户资料贡献到聊天上下文；其 `MemoryAutoSaveScheduler.kt` 则分开处理后台候选、批次及资源上限。参考 DSH `packages/core/agent-loop/src/agent.ts` 的每步 `preStep` 重新组装，`packages/compaction/compaction-basic/src/config.ts` 的输入/输出预算分离，以及 `region.ts` 与 `tests/compaction-basic.spec.ts` 的工具配对和摘要事务。采用行为和职责划分，未直接复制上游实现代码。

先交付 TS 自动检索与每步刷新，随后实现全请求预算和可查看摘要，保留后台记忆候选这一完整目标。自动检索只读取已经保存的记录，不代表后台自动抽取已完成；对不同模型的 Token 估计不能冒充 Provider 实测 usage。

API 7 提供原生布尔配置开关和 `beforeModel` 输入中的非密钥配置快照。仅声明为非 `secret` 的字段由宿主读取；Hook 仍不能访问密钥、执行写入、联网或启动工具。旧 API 的输入契约保持兼容。客户端、打包和市场按 API 版本过滤，新增包上线前验证旧客户端下载及字节校验。

所有构建和测试通过 GitHub Actions；验证证据按实际结果补充，不宣称真实模型或真机已完成验收。

Agent 每个模型步骤重新取得允许的工具及 Hook 上下文，以原始身份/规则作为固定基础，不累积旧 Hook 文本；工具保存或删除记忆后，下一模型步骤可看到最新检索。新回归检查同一回合从旧记录到新记录的变化，仍保留唯一身份。

记忆插件 1.1.0（API 7）注册只读 `beforeModel`，检索相关记录并补充明确用户画像，记录带来源/ID/更新时间。最多六条，每条正文最多 700 个 Unicode 字符，记录 JSON 最多 6,000 个 UTF-16 字符；这只是记忆贡献上限，不等于全请求 Token 预算。布尔开关关闭时不读取存储。保存、删除、批量抽取仍需工具授权，没有新增后台模型调用。

API 1 旧包保留给旧客户端；已安装 1.0.0 不静默替换为含自动上下文的新版本，用户通过市场更新并重新启用。新安装版本启用时说明已保存资料可能提供给当前模型；配置可关闭自动检索，停用或角色未绑定均不注入。

新增真实 QuickJS→宿主私有存储→Agent→SQLite 聊天集成回归：一次工具保存后下一步骤注入；宿主/数据库重启后新会话无需工具调用即可取到偏好；开关关闭、角色未绑定、删除和停用均不再注入。Provider 使用受控响应，此测试不代表真实模型已经遵守记忆。

记录截断时返回 `truncated` 标记，避免把片段误当作完整资料。模拟器回归检查原生布尔开关从开启切到关闭、保存并重新打开；存储错误与关闭不读取通过不同层次回归覆盖。

自动检索会在每个模型步骤运行，因此 BM25 的文档频率改为每个查询只统计一次，避免每条候选重复扫描全部记录。新增 512 条记录的受限语料回归，验证来源、输出上限及 Hook 预算内完成；Node 验证耗时不等于 Android 真机耗时。

增加实际 Android QuickJS/Keystore/插件宿主→应用 Agent→Provider 请求的模拟器回归，直接检查已保存偏好进入请求、无需模型调用检索工具及诊断不保留资料正文。Provider 仍为受控实现，不能据此宣称真实模型遵守记忆。512 条语料还在实际 QuickJS JVM 引擎的 32 MiB/Hook 期限内验证，真机性能另行验收。
