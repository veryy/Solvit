# 插件自带界面：记忆插件作为第一个完整示例

用户要求插件既能供模型调用，也能提供可查看和操作的界面。当前 TS 承载记忆业务，`MemoryManagementScreen` 仍硬编码在 Kotlin，不能称为插件自带界面。先完成自动记忆版交付，随后优先实现通用插件页面，再推进工作区执行链。

已读取锁定 Operit 的 `ui/features/memory/screens/MemoryScreen.kt`：搜索、目录导航、持续挂载的 GraphVisualizer 和查看/操作入口；DSH 的 `skills/cordis-plugin-development/references/ui-plugin.md`：页面/插槽注册、宿主主题、延迟加载、卸载清理和客户端本地化。实现前继续读取对应组件与测试。DSH 的 React/浏览器组件不能直接运行在 Android QuickJS；第一步采用 TS 页面声明与事件处理、Compose 原生渲染。

目标接口：插件清单注册页面；JS/TS 返回有界的视图树和页面数据，处理搜索、分页、导航、编辑及确认操作。宿主提供列表、卡片、标签、表单、详情及图关系展示等通用组件，不为每个插件单独编写 Activity。页面继承应用主题、语言、字体及系统边距。配置字段声明与完整页面分别支持，不能把几个开关当成插件业务界面。

记忆示例须提供事实列表/搜索、角色与类别筛选、原文来源详情、编辑/删除、关系查看及后台任务入口。数据和操作由 TS 记忆插件实现，继续复用原子存储；宿主任务状态和来源退休接口提供受限桥接。应用设置和插件详情页都能打开插件页面，保留现有数据。

页面采用独立执行实例，避免阻塞模型 Hook 或后台抽取。页面回调不是免审批的模型工具调用；访问存储、网络、文件和 Shell 仍受宿主权限与实时撤销检查，清理和删除由宿主确认。原生人工管理可在插件停用时使用的现有行为需要明确迁移策略，不能把不可信下载页面直接赋予内置管理器的免授权能力。

验收：新增一个带页面的示例插件，无需改 App 页面代码即可展示和交互；真实 QuickJS→页面协议→Compose→回调→持久存储验证；记忆编辑/搜索、主题语言、返回关闭和卸载清理；后台等待时页面可响应；权限撤销、无效/过大视图及插件升级兼容。通过 GitHub Actions 单元、模拟器、Lint、APK 后交付；当前只是确定接口和验收范围，尚未实现。
