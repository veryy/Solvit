# 对话、工作区与 Shell

新对话默认没有工作区，只进行聊天。点击“新建工作区”后才创建目录、Shell 1 并绑定；也可以绑定已有工作区。每个对话最多绑定一个工作区，多个对话可以共享同一工作区。一个工作区最多 16 个命名 Shell 会话。删除对话只删除绑定，保留可复用的工作区文件和 Shell 会话。

“聊天 → 工作区”提供‘Shell’和‘工作目录’两个标签，可查看实际目录、浏览子目录并编辑文本文件。每条命令从对应工作区根目录启动，默认以应用 UID 执行，可选择普通命令或交互终端。Shell ID、工作区和对话绑定跨重启保存；运行任务与输出当前仅在进程生命周期内保留，进程关闭后不会恢复任务。

“普通命令”每次启动独立进程；`cd` 和环境变量只影响本条命令。“交互终端”使用真实 PTY，在同一进程内保留目录、环境和交互提示；交互页面使用插件离线HTML/JS与xterm.js绘制终端。直接键盘输入为原始字符，底部便捷命令输入追加换行；Ctrl-C中断前台命令，关闭终端结束会话。同对话AI终端可在列表中选择，须经过原生确认才可查看与输入；跨对话不允许，即使共享工作区。关闭页面不等于关闭手动PTY。

新增 `terminal-android` Kotlin 宿主插件 `builtin.pty`，提供可替换 `TerminalService`。API 5 的独立 JS/TS 插件 `dev.solvit.terminal` 提供 `terminal_open/status/input/interrupt/close` 工具；先用工作区插件获得 Shell ID。模型发送的输入是原始文本，执行命令或回答提示时须自行追加换行，然后轮询状态读取输出。

PTY 按插件、角色、工作区、Shell 和执行身份隔离。同一个名字的 Shell 可以有不同插件拥有的进程；插件页面显示会话来源。最多 8 个活动终端、16 条历史，每个保留最近 65536 个字符。进程不会跨重启恢复；同一会话内的目录和环境保留，重新打开关闭过的终端会创建新进程。取消本轮 Agent 执行会关闭本轮使用的终端；停用插件、执行身份变化会关闭该插件终端。

当前 PTY 使用普通应用身份，Root 模式会明确拒绝 PTY 启动，可切回普通模式或使用原有 Root 非交互命令。尚无 Root PTY、Shizuku和 SSH/SFTP；PRoot/Ubuntu发行版已在0.31.1交付，见下方安装说明；交互界面使用xterm.js处理VT屏幕与原始按键，但vim/top等全屏TUI、真机输入法和Root环境尚未验收。

`workspace-android` 是注册 `WorkspaceService` 的 Kotlin 宿主插件，负责本机文件与子进程能力。工具逻辑在 `dev.solvit.workspace` JS/TS 插件中。启用“工作区与 Shell”并授予权限后，AI 可发现当前工作区、读取/写入文本、创建 Shell 会话、启动命令、轮询输出与停止任务。

工具通过不可由 JS 伪造的 `ConversationContext` 获取当前对话工作区。实际宿主参数必须与用户确认的完整工具 JSON 一致；不同命令、路径和文件内容会被拒绝。Shell 状态与停止还检查所属插件、角色和工作区。取消 Agent 回合会停止本轮启动的命令；停用/卸载插件停止它的任务。每个工具会请求确认。

普通文件 API 只接受当前工作区内的相对路径并检查规范路径，文本最多 256 KiB。Shell 本身具有本应用 UID 的文件与网络权限，工作目录限制不是操作系统沙箱；不要把 shell 授权理解成仅能访问某个目录。QuickJS 不直接暴露 Node、Java 反射或文件系统。

执行器当前最多 8 个活动任务、32 条任务历史；单任务默认 60 秒，输出只保留最近 64 KiB / 256 段。用户停止和超时会关闭进程 stdin，触发专用进程组的终止与回收。

## 执行权限

设置 → 权限与执行方式：查看应用 UID、su 检测结果及授权状态，为手动终端和声明 shell 权限的插件分别选择普通或 Root 模式。Root 只在原生界面请求，JS 不能自行选择或升级身份。每次 Root 命令前检查 `su -c id -u`；拒绝、撤销或超时不会回退到普通模式。选择跨重启保存，Root 授权状态不被假定为永久有效。切换模式停止该插件现有任务，并使此前工具确认失效；Root 工具确认卡和任务记录显示执行身份。

Root 可以操作整个设备；普通文件 API 仍限定在工作区内。不同 Root 管理器与真机尚未验证。Shizuku、无障碍和其他设备操作接口仍待接入。

工作区概念参考 [VS Code](https://code.visualstudio.com/docs/editing/workspaces/workspaces)：目录与运行上下文。终端会话接口参考 [Operit Terminal](https://github.com/AAswordman/OperitTerminal)；PTY 实现为独立编写的 POSIX/JNI 后端，未复制其代码。Ubuntu环境已按其PRoot用户空间思路独立适配，参考版本、许可证和实际执行证据见[环境阶段](linux-environment-stage.md)。

API13离线终端包1.1.0与APK一致，API5–12市场继续提供原始1.0.0。仅字节匹配的旧内置包自动升级并保留启用与授权；修改包和卸载状态不覆盖。接口见[插件终端页面](plugin-terminal-pages.md)，验证与未完成范围见[0.22.3候选](release-0.22.3.md)。

## Linux 开发环境（已在0.31.1发布）

打开「工作区 → Linux」下载 Ubuntu。安装结束后点「新建 Ubuntu Shell」，该 Shell 会持久保存 `UBUNTU` 运行环境。Python/venv、Node24/npm 随基础安装提供，Python/pip 和 Java17 可以继续安装。新建的 Ubuntu Shell 与 Android Shell 使用同一个工作目录；终端和 AI 命令都映射到 `/workspace`，文件管理立即看到脚本输出的文件。

没有工作区时也能安装全局环境，但必须先创建/绑定工作区才能添加 Ubuntu Shell。原有 Android Shell 不自动改名或切换运行环境。Linux 页面提供进度、近期日志、停止和重试；失败的初次安装保持未安装，重装失败保留已启用环境。

该环境使用 Android 内核和应用身份，不获得 root 或额外 Android 权限。当前 ARM64/x86_64 提供程序，API35 x86_64 设备测试与 ARM64 真机状态请看 [验收记录](linux-environment-stage.md)。Node24 的官方 Linux 支持基线为内核4.18以上；旧手机的兼容性须实际验证。公开版本与下载以 Release 为准。


## 文件导入与预览（已在0.34.0发布）

0.34.0的正式APK与下载核对见[发布记录](release-0.34.0.md)。升级后打开「工作区 → 文件 → 导入文件」，选择一个最多20MiB的文件，先查看名称、类型、大小与目标位置，再点确认导入。需要写入子目录时先创建目录；路径必须位于当前工作区内。0.37.0起同名文件先审阅目标大小与摘要，明确确认后检查版本并保留原文件备份；也可返回改名。

文本/代码可以预览UTF-8正文，超限或二进制明确提示。图片可按需生成缩略图，PNG/JPEG/WebP/GIF支持、动图只看首帧；缩略图的大小和白底不改变实际导入的原文件。导入后在文件树、Git Changes和Shell里看到的是同一个文件。系统选择器取消保留此前选择，放弃选择/关闭页面释放当前选择；单纯查看预览不创建工作区文件。

0.35.0已支持PDF原页和文字分页预览，聊天选页与预览不会替换完整原文件。0.36.2已支持从当前对话已保存附件导入；0.37.0已支持带版本确认的替换和原文件备份，0.38.0已支持导入进度、取消与登记式暂存回收。完整范围和实际设备证据见[导入阶段](workspace-import-stage.md)。


## 从已保存聊天附件导入（0.36.2）

在当前对话的「工作区 → 文件 → 从聊天附件导入」选择附件，核对来源消息、名称、类型、大小、摘要与目标路径。选择不会写工作区，可以先预览文字、图片或PDF原页；确认后导入完整原文件，聊天中的PDF选页和OCR不会替换原PDF，原聊天附件继续保留。文件管理、Git Changes和Shell使用同一份导入文件。0.37.0支持同名审阅和带版本检查的替换；0.38.0已交付进度取消和登记式暂存回收。[正式版本与验证](release-0.36.2.md)。


## 审阅和替换已有文件（0.37.0）

确认导入时如果目标已存在，先查看已有文件大小和SHA256，再点「确认替换并保留原文件」。审阅后若Shell又改过目标，本次确认失效，需要重新审阅。取消会回到原选择，不替换文件。

成功后页面显示原文件的 `solvit-backup-UUID` 相对路径，备份和新文件都在同一个目录，文件管理、Git和Shell都可访问。检查后手动删除备份；目前不会自动回收。失败时会尝试恢复原名字，遇到同名竞争则保留双方并提示恢复路径。操作不锁住外部进程，旧名字移走到新文件发布之间有短暂空窗。源和目标均限20MiB普通文件。实际场景和公开APK核对见[0.37.0发布记录](release-0.37.0.md)。


## 导入进度与取消（0.38.0）

[0.38.0已发布](release-0.38.0.md)。确认导入后会显示实际写入工作区暂存的字节、同步/校验/发布阶段；这不包含系统选择器读取或网络下载的进度。点击「取消导入」并确认后等待清理，成功取消时保留原选择，可重新审阅再导入。文件已经发布时，晚到的取消不会把成功结果改成失败。

替换取消会尝试恢复原名字；若Shell恰好又创建了该名字，会保留双方并提示备份恢复路径。关闭页面同样等待任务清理。下次启动只回收宿主在工作区外登记、且身份仍一致的暂存文件；不会仅凭`.solvit-import-*.partial`文件名删除文件，也不自动删除原文件备份。

这不等于完整进程死亡事务恢复：系统强杀若发生在原名字移走后，原文件备份仍在，但自动恢复名字尚待后续事务日志。完整验收、真实界面失败与修复见[阶段记录](workspace-import-transfer-stage.md)，请以正式Release为准。

## 重启后的导入恢复（0.39.0）

应用在替换文件时被系统结束，重启后会检查未完成的导入。打开原对话的「工作区 → 文件」，有恢复结果时会显示「上次导入恢复」，点「查看详情」查看具体文件；没有结果则不显示这张卡片。

- 原文件已经放回原位置时，可以直接继续使用它。
- 文件已经发布时，保留发布结果及原文件备份；即使Shell后来删除了新文件，也不会自动放回旧文件。
- 遇到并发同名或无法确定的情况，会保留文件和备份，显示需要检查的相对路径。

「关闭提示」只清除这条提示，文件和备份继续保留。每页最多5条、最多查看最近100条。检查备份内容后再决定如何处理；目前没有自动删除备份或容量配额管理。此机制面向进程结束，不承诺断电、磁盘损坏或任意外部Shell修改下的自动恢复，也不会重新发送模型任务或重复执行Shell。

[0.39.0已发布](release-0.39.0.md)，正式五场外部强杀/重启及完整设备回归通过，见[实际证据](workspace-import-recovery-stage.md)。

## 导入前的空间检查（0.39.1）

写入工作区之前，会检查完整新文件大小加4MiB余量，同一存储卷上的其他导入预留也会计入。已知空间不足时直接显示可用、需要和预留字节数，原文件不动，当前附件选择保留。释放空间后重新审阅并确认即可重试；不会自动删除备份腾空间。

这只是开始前的观察，Shell或其他应用之后仍可能消耗磁盘，实际写入失败会走已有清理/恢复流程。[实际设备与发布证据](release-0.39.1.md)
