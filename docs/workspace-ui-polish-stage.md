## 实际问题

已查看真实设备归档中的 `workspace-directory.png`：窄屏里“文件”入口占一整行，路径与五个同等级操作挤在文件列表上方；底部“刷新”被当作主操作。空目录仍被操作按钮占据大量空间。这不是仅换颜色能解决的问题。

当前实现位于 `builtin-plugins/workspace/pages.ts` 的 `mode==='list'` 和插件自己的 `ui/main.mjs`、`ui/style.css`。目录、新建、导入、备份、编辑及确认已有真实业务协议，不应另写一个原生文件管理器或绕开其确认。

## 下一步实施边界

1. 路径、上级导航、文件树和刷新形成紧凑导航区；用有名称的按钮保留触摸与无障碍入口。先处理窄屏，不把整排桌面工具栏塞入手机。
2. 新建文件/目录归入“新建”，设备文件/聊天附件归入“导入”，备份归入“更多”；展开只改变显示，选择具体项才发送既有事件。保留原事件标识、权限、容量、覆盖审阅与进程恢复。
3. 文件列表优先占空间，行展示名称和类型/大小，移动/删除等次要操作不与打开争抢视觉优先级。空目录应给出可执行入口，错误不能伪装为空目录。
4. 不将文件树展开、刷新、重开、放弃编辑当成自动重放写入的机会；未保存、确认、导入进度及后台操作仍依原协议处理。
